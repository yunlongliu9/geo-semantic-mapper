Teil 04 · Vorlage und Evidenzinstanz

Die Vorlage ist Konfiguration; die Evidenz dokumentiert eine Ausführung

Vorher · Vorlage

mapping:Evidence001

rdf:type EvidenceTemplate
operator Equals
feature Surface
evidenceType Supporting
result Compatible

Definiert die Einordnung, falls die beiden Eigenschaftswerte übereinstimmen.

Nachher · Instanz

mapping:GeneratedEvidence001

rdf:type Evidence
derivedFromTemplate Evidence001
generatedBy R001
sourceValue "asphalt"
targetValue "asphalt"
result Compatible

Speichert die tatsächlich verglichenen Werte und das Ergebnis eines Laufs.

Der Prototyp nutzt ein eigenes RDF-Vokabular. rdf:type mapping:Evidence ist eine Typaussage über eine Instanz, keine explizite RDFS-Klassendefinition.

Teil 05 · Mapping-Regel

R001 verknüpft drei Entscheidungszweige über RDF

mapping:R001 a mapping:MappingRule ;
    mapping:feature mapping:Surface ;
    mapping:onMatch mapping:Evidence001 ;
    mapping:onMissing mapping:Evidence002 ;
    mapping:onMismatch mapping:Evidence003 .
onMatchEvidence001 → Equals
onMissingEvidence002 → EitherMissing
onMismatchEvidence003 → NotEquals
template = mapping_graph.value(rule_id, MAPPING.onMatch)
operator = mapping_graph.value(template, MAPPING.operator)
# R001 → Evidence001 → Equals
RDF speichert die Regelkonfiguration; Python implementiert die Semantik von Equals / NotEquals / EitherMissing.
Teil 06 · evaluate_rule() · Auslesen

Vergleichsparameter dynamisch aus dem Graphen lesen

branches = [
    MAPPING.onMatch,
    MAPPING.onMismatch,
    MAPPING.onMissing,
]
for branch in branches:
    template = mapping_graph.value(rule_id, branch)
    if template is None:
        continue

    source_concept = mapping_graph.value(
        template, MAPPING.sourceConcept)
    target_concept = mapping_graph.value(
        template, MAPPING.targetConcept)
    source_property = mapping_graph.value(
        template, MAPPING.sourceProperty)
    target_property = mapping_graph.value(
        template, MAPPING.targetProperty)

Teil 06 · evaluate_rule() · Ausführen

Tatsächliche Werte lesen und Operatoren ausführen

source_value = osm_graph.value(source_concept, source_property)
target_value = atkis_graph.value(target_concept, target_property)

missing = source_value is None or target_value is None
if operator == MAPPING.EitherMissing:
    matched = missing
elif missing:
    matched = False
elif operator == MAPPING.Equals:
    matched = source_value == target_value
elif operator == MAPPING.NotEquals:
    matched = source_value != target_value

Alte Evidenz ersetzen und tatsächliche Vergleichswerte speichern

Vorherige Evidenz entfernen

old = mapping_graph.value(

if old is not None:

        candidate, MAPPING.hasEvidence, None

In dieser Demo wird pro Kandidat jeweils nur die neueste Evidenz gespeichert.

if evaluation["source_value"] is not None:
    mapping_graph.add((
        evidence, MAPPING.sourceValue,

    ))

mapping_graph.add((
    candidate, MAPPING.hasEvidence, evidence

Teil 08 · Entscheidungszustand

Warum alte Relationen löschen und .set() verwenden?

Alte SKOS-Aussagen entfernen

for relation in (
    SKOS.exactMatch,
    SKOS.relatedMatch
):
    mapping_graph.remove((
        source, relation, target
    ))

Verhindert, dass frühere exactMatch- und relatedMatch-Aussagen für dasselbe Konzeptpaar bestehen bleiben.

Aktuelle Entscheidung speichern

mapping_graph.set((
    candidate,
    MAPPING.decision,
    decision if decision is not None
    else MAPPING.NoMapping
))

.set()ersetzt den bisherigen Wert für dasselbe Subjekt und Prädikat, statt weitere Werte anzuhängen.

osm:Road skos:exactMatch atkis:Road ist eine Relation zwischen Konzepten; Candidate001 mapping:decision skos:exactMatch ist dagegen ein Entscheidungsmetadatum.
Teil 09 · End-to-End-Orchestrierung

run_mapping()koordiniert die drei Verarbeitungsschritte

def run_mapping(osm_graph, atkis_graph, mapping_graph):
    candidate = MAPPING.Candidate001

    evaluation = evaluate_rule(
        osm_graph, atkis_graph, mapping_graph, MAPPING.R001)
    if evaluation is None:
        raise ValueError("No matching rule branch")

    evidence = generate_evidence(mapping_graph, candidate, evaluation)
    decision = make_decision(mapping_graph, candidate, evaluation)
    return decision

EntscheidenSKOS-Mapping schreiben

Vorstellungsgespräch · Zusammenfassung (B2–C1)

So erkläre ich das System im Vorstellungsgespräch

„In meinem Prototyp modelliere ich OSM- und ATKIS-Konzepte als RDF- beziehungsweise SKOS-Ressourcen. Die Mapping-Regeln und Evidenzvorlagen werden strukturiert im Mapping-Graphen gespeichert. Eine Python-Komponente liest die Vergleichsbedingungen, wertet Eigenschaften beider Quellen aus und erzeugt nachvollziehbare Evidenzen. Anschließend wird das Ergebnis als SKOS-Mapping-Relation gespeichert. Die Pipeline habe ich mit drei Testszenarien validiert.“
